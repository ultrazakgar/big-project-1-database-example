# Проект базы данных для игры Рулетка (MySQL)

## Схематичное взаимодействие игры с базой данных

Игрок заходит на сайт, ему ставится в соответствие строка таблицы `roulette_session`, Поле `sessionid` этой строки сохраняется в куках или в `localstorage` посетителя.

Прогресс пользователя сохраняется в поле `userdata` строки таблицы сессий.       

В момент, когда по окончании очередной игры пользователь вводит свое имя, создается запись в таблице `roulette_users` и соответствующая запись в таблице `roulette_score`. При продолжении игры, таблица со счетом дополняется.

## Таблица сессий

`roulette_session`  - таблица для хранения текущего состояния игрока. Предполагается генерация sessionid для каждой новой строки, которая бы обеспечивала уникальный для таблицы сессий идентификатор.
`sessionid` сохраняется в броузере пользователя и используется для восстановления прогресса игрока между посещениями сайта.
`user_id` - в случае, если пользователь авторизовался на сайте, значение вписывается. По нему можно восстановить все сессии этого игрока и осуществить объединение прогресса, если это предполагается игрой. Прогресс авторизованного игрока хранится в данных таблицы `roulette_users`
`userdata` - JSON данные, которые содержат накопленное состояние игрока.
`created` - время создания сессии. По этому полю можно периодически удалять сильно устаревшие, неиспользуемые сессии.

При создании новой сессии достаточно записать пустые данные

	INSERT INTO `roulette`.`roulette_session` (`userdata`) VALUES ('{}');

Затем , используя `LAST_INSERT_ID` получить вставленную строку с уже сгенерированным sessionid.

Хотя, более корректно - использовать хранимую процедуру для выполнения этого действия атомарно.

    DROP PROCEDURE IF EXISTS CreateNewSession; -- для отладки процедуры,
    -- удобно размещать ее в одном SQL блоке, вместе с использованием. 
    -- После отладки, для эффективности, разумно разнести описание и использование процедуры.
    DELIMITER //
    
    CREATE PROCEDURE CreateNewSession(
        IN p_data JSON,
        OUT p_session_id varchar(32)
    )
    BEGIN
        SET p_session_id = UUID_SHORT();
        INSERT INTO roulette_session (sessionid,userdata) VALUES (p_session_id,p_data);
    END //
    
    DELIMITER ;

    -- использование хранимой процедуры
    
    CALL CreateNewSession('{}', @sessionid);
    select @sessionid as sessionid;

Создание новой сесcии и получение `sessionid`. (шаблон запроса)

    CALL CreateNewSession(?, @sessionid);
    select @sessionid as sessionid;

Получение состояния игры при наличии `sessionid`. (шаблон запроса)

    select userdata from roulette_session where sessionid=?;

Обновление состояния игры при наличии `sessionid`. (шаблон запроса)

    update roulette_session set userdata=? where sessionid=?;

## Таблица пользователей 

Таблица служит для хранения зарегистрированных на сайте пользователей. Логин пользователя является уникальным для каждого клиента.
В таблице используется внешний ключ для обеспечения целостности связки таблицы пользователей и таблицы счета.
`user_id` - ID пользователя, 
`name` - ник пользователя для вывода в таблице рекордов. Ключ в базе стоит неуникальный, так как уникальность или неуникальность ника определяется логикой игры.
`data` - прогресс пользователя,
`banned` - возможность исключить пользователя из таблицы рекордов, без удаления его записей (1 - заблокирован)

## Таблица счета игрока

Таблица используется для хранения глобальной таблицы рекордов в игре.
Каждой записи в таблице соответствует счет и зарегистрированный в системе аккаунт, что позволяет вывести таблицу рекордов из 20 лучших игроков.
`user_id` - ID пользователя,
`score`, 
`created`

Получение 20 верхних записей в таблице рекордов

    select s.score, s.created, u.name from roulette_score s
    join roulette_users u on u.user_id=s.user_id
    where u.banned<1
    order by s.score desc
    limit 20


## Описание содержимого репозитория

Скрипт `create.tables.sql` пересоздает все таблицы в базе данных и хранимые процедуры. Все имеющиеся данные будут удалены.

Для быстрой проверки работоспособности внешнего ключа и хранимых процедур служит скрипт заполнения тестовых данных `temporary.data.sql`

ER диаграмма базы в файле `er.roulette.pdf` 

При разработке базы данных использован MySQL Workbench.
